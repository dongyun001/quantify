# 量化积分管理系统

学院量化积分的线上化系统：把原先手工维护 Excel 的「记分 → 汇总 → 排名 → 导出」流程，
变成 **部门录入 → 审核员审批 → 自动汇总 → 一键导出** 的完整闭环。

> 本仓库只公开源码，用于版本留痕与回滚。需求、设计、部署等内部文档不在此仓库内。

---

## 它解决什么问题

手工 Excel 记分的典型问题是：多个部门各拿一份表、合并靠人肉、总分和明细对不上、
改过的分数查不到是谁改的。这个系统把这几件事拆开处理：

- **录入**：按「学生 + 类别 + 分值 + 事由 + 日期」落一条流水，支持单条录入和 Excel 批量导入；
- **审批**：草稿 → 待审 → 通过 / 驳回，驳回必须写理由，记录保留不删；
- **汇总**：总分不落库，每次实时聚合，从根上避免「总分和明细对不上」；
- **留痕**：每次写操作记审计日志，含改动前后快照；
- **导出**：页面和导出走同一套聚合逻辑，杜绝「页面 8 分、导出 11 分」。

## 主要能力

| 模块 | 说明 |
|---|---|
| 登录与权限 | 角色（ADMIN / EDITOR / VIEWER）+ 数据范围，接口级鉴权，登录失败限流，首登强制改密 |
| 学生与班级 | 学生查询、转班、离班、复学；班级管理（仅管理员） |
| 积分流水 | 录入、编辑、提交、撤回、变更申请 |
| 审批 | 通过、驳回、打回重做、管理员撤回、管理员变更 |
| 五育类别 | 德 / 智 / 体 / 美 / 劳，加分扣分都必须归类 |
| 总分与明细 | 实时聚合、全局排名、学生明细 |
| Excel | 按班分 sheet 导出；批量导入支持逐行预览校验、整批撤回 |
| 申诉 | 学生对本班已通过记录申诉，一级受理（走变更链更正）或驳回，可推送钉钉通知 |
| 账号管理 | 账号增删改、按班批量开户、重置密码 |
| 操作日志 | 全量写操作留痕，可查改动前后值 |

## 设计上的几条硬规则

1. **分值恒为正数**，加分/扣分由类别字段决定；扣分的负号只出现在聚合 SQL 里。
2. **总分不落库**，没有任何缓存或定时重算，永远是实时聚合。
3. **已通过的记录不可就地修改**，只能新建变更记录，原记录置为失效，变更链完整可追溯。
4. **数据范围只由登录身份推导**，不接受前端传 `classId` / `scope`；越权返回 403 而不是空列表。
5. **权限判定在后端**，前端菜单过滤只影响体验。
6. **逻辑删除**，流水与学生都不做物理删除。

## 技术栈

| 层 | 选型 |
|---|---|
| 后端 | Spring Boot 3.5 + Java 21 |
| ORM | MyBatis-Plus（单表 CRUD）+ XML（聚合查询） |
| 鉴权 | Sa-Token，密码用 BCrypt |
| 数据库 | MySQL 8.0 |
| Excel | EasyExcel（流式写入） |
| 前端 | Vue 3 + Vite + TypeScript + Element Plus + Pinia |

没有引入 Redis、消息队列、分库分表——当前数据规模用不上。

## 快速开始

前置：Docker Desktop、JDK 21、Node 20+ 与 pnpm。

```bash
# 1. 起数据库（首次自动建表）
docker compose up -d

# 2. 起后端
cd server && ./mvnw spring-boot:run

# 3. 起前端（另开终端）
cd web && pnpm install && pnpm dev
```

默认端口：MySQL `3307`、后端 `8090`、前端 `5174`。
数据库密码与初始管理员密码通过 `DB_PASSWORD` / `INIT_ADMIN_PASSWORD` 环境变量覆盖，
未设置时用本地开发默认值；部署到服务器时务必显式设置。

### 钉钉通知（可选）

申诉创建与处理结果可推送到钉钉群，使用群自定义机器人的 Webhook + 加签。
未配置时静默跳过，不影响申诉功能。配置项为 `quantify.dingtalk.*`，
通过环境变量 `DINGTALK_ENABLED` / `DINGTALK_WEBHOOK` / `DINGTALK_SECRET`，
以及 `DINGTALK_NOTIFY_REVIEW`（受理/驳回结果是否也发，默认 true）注入。

消息在申诉事务提交后异步发送；发送失败不回滚业务，可在页面上手动重试。
